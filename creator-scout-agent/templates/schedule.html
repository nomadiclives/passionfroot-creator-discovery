Discovery schedule

Pre-builds a soft roster for every campaign in the pipeline, so the shortlist exists before the brief is signed.

Nothing here fires on its own. The cadence is a saved setting, not a running timer.

Run now works — it runs the whole pipeline immediately and writes a dated roster you can read below. That part is real, and it is the quickest way to see what this produces.

The cadence and “next run” are not. The repeating loop lives in scheduler.py, which has to be running as its own process. The web app never starts one, so the date below is arithmetic rather than a promise. On the hosted version there is no such process at all — the deployment defines a single web service, and a free instance sleeps when idle, so a timed run would not survive the night even if one existed.

To have it genuinely run on a cadence: python scheduler.py alongside the app, or a worker or cron job on a paid plan. Until then this page is a console for a scheduler that is only ever run by hand, and saying so seemed better than showing a next-run date nobody is keeping.

What this page is for

Building a shortlist by hand takes days, and briefs usually arrive with less notice than that. The idea is that the whole pipeline runs against the campaigns you know are coming, so a rough shortlist already exists on the day a brief is signed rather than starting from nothing. The pipeline and the run are built and work; what is missing is anything to trigger them on a clock — see above.

  1. Cadence records how often that should happen and drives the next-run arithmetic. Run now does one immediately, and is the only thing on this page that actually starts a run.
  2. Pipeline is the list of upcoming campaigns it runs for. It is edited in a file, not here.
  3. Last run reports how each campaign came out. A high Review count is normal and is explained under that table.
